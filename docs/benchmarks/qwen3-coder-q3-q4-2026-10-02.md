## CODE-FIX-001 — admin panel edit workflow

Real-world debugging task on `tabacalera-app`.

Symptom: Edit buttons for Users and Transporters did not complete the edit flow.

### P1

An initial Q4 run completed but misidentified a secondary cancel-form visibility issue as the root cause.

### P2

A stricter prompt required explicit frontend/backend contract tracing:

button -> handler -> fetch -> method/path -> Express route -> Sequelize query -> JSON response -> form -> PUT -> refreshed list.

Q4 then independently identified the primary mismatch:

- frontend required `GET /api/admin/users/:id`;
- backend did not expose `GET /users/:id`;
- frontend required `GET /api/admin/transporters/:id`;
- backend did not expose `GET /transporters/:id`.

The agent added the two missing GET-by-ID routes and passed `node --check` on the relevant JavaScript files. Human functional validation/deployment remains the final acceptance step.

This task demonstrates that prompt structure is itself an experimental variable: completion does not imply root-cause accuracy, and explicit evidence/contract tracing materially changed behavior.

## Q3 vs Q4 performance caution

The earlier Q3 LAILAB-B002 result of about 69.1 tok/s TG128 is a direct short benchmark and is NOT directly comparable with the ~29.7 tok/s Q4 agentic-session average. Workload, context length, KV-cache state, request size and tool overhead differ.

A valid speed comparison requires identical workload, context, llama.cpp build, offload settings, cache state, OpenCode version/mode and repeated runs.

## Operational decision

Keep Q4_K_M at 49,152 context for daily coding. A real task reached about 39K without compaction, so reducing the daily profile to 32K would remove useful headroom.

Keep the existing Q3_K_M/32K BENCH-CODE-001 formal baseline immutable.
